# Simba Agentic Intelligence 26.3: relationship to this Composer MCP

Written 29 September 2026, before 26.3 is released. Everything below is
forthcoming rather than observed. Nobody has run a 26.3 instance and no
procedure here has been executed, so read this as a warning about what
changes, not as instructions. `SI_26.2_NOTES.md` stays correct for 26.2.

Sources are Jira keys in PY (Simba Agentic Intelligence, "SI" below), SCP and
CMP (Composer), Confluence page ids in the SCP and PJX spaces, and the public
Composer documentation site. Composer facts that are already public carry
their public URL.

## The change that breaks working code: SI stops being its own deployment

From 26.3, SI ships as a sub-component of the Composer Helm chart (PY-693).
There is no separate SI chart (PY-701), and the arrangement several files in
this repo assume, a standalone SI chart pointing at a separately hosted
Composer, is recorded as no longer supported in 26.3 and later (Confluence
page 18711380170, SCP space).

Three consequences for anyone driving Composer from this MCP:

- **The context path moves.** SI served from root `/` becomes
  `{composer-context}/intelligence`, default `/composer/intelligence` (page
  18711380170). The context path stays configurable, so `/discovery` survives
  where an admin sets it and stops being what you get by default. Every
  `/discovery/...` literal in this repo records the 26.2 default, not a
  constant.
- **The SI UI and its frontend APIs are removed.** A breaking change rather
  than a redirect. Anything bookmarking SI's own pages or calling its frontend
  endpoints needs rework.
- **A standalone SI customer with no BI still deploys the Composer chart.**
  That is a requirement of the packaging, not a convenience.

The transition guide for existing deployments is ticket PY-706, which was
unfinished when this was written. There is no documented upgrade path to point
at yet, so do not improvise one.

Composer's own 26.3 documentation is public and states that Kubernetes is
supported for new installations only from 26.3 onwards, via the Helm chart
`composer/composer`:
<https://insightsoftware.mintlify.app/simba-embedded-analytics/docs/self-service-analytics/26.3/>

## Sign-in

Single sign-on with Composer is not new; it shipped in 26.2 (PY-530,
Confluence PJX/18483511372). What 26.3 adds is that SI stops having a login of
its own, so it inherits Composer's SAML rather than implementing SAML. PY-689
gives the reason plainly: SI's own login does not work with SAML, Composer's
does. SAML was exercised against a 26.3.0 build under SCP-454 and CMP-8739.

One Composer defect is still open. SCP-1124 records the Custom User Attribute
fields on Composer's SAML admin page as not editable, leaving attribute
mapping unusable from the UI. Check it before relying on attribute mapping in
a 26.3 SAML deployment.

## SI's native MCP grows a visual surface

`SI_26.2_NOTES.md` describes SI's own MCP server as four read-only tools. 26.3
adds tools for creating, retrieving and rendering visuals, and for opening a
generated visual in Composer. The originating design is Confluence
PJX/18246598721. The division of labour between SI's MCP and this one moves
with it: rendering a visual stops being only a Composer authoring job.

Three qualifications matter more than the headline.

- **This is not "you can now build a visual by asking".** Composer 26.2
  already ships visual creation from natural language on the home page, in the
  Visual Gallery and inside dashboards, and `CHATBOT_EMBED.md` already
  documents the SI chatbot rendering live Composer visuals inline when you
  pass it the embed manager. What is new is the rendering surface moving into
  a third-party AI client.
- **Dashboards are excluded and unscheduled.** PY-631 sits in the backlog with
  no fixVersion, and PY-536 deferred `get_dashboards` explicitly.
- **Deployment precondition.** MCP must be served at root (`/`) or disabled
  entirely (page 18711380170), described there as a protocol limitation and
  explicitly not fixed for 26.3. That sits awkwardly beside the context-path
  move above, so read the page before planning a deployment around it.

26.3 also hardens the MCP OAuth flow (server-side request validation, PKCE
enforcement, exact redirect matching) and adds a breaking change requiring the
canonical MCP base URL.

## Administration moves into Composer

LLM configuration and agentic rules move under Composer's
Administration > Tools area, scoped to four items under epic SCP-314
(Confluence page 18773016632). Existing rules keep working: SCP-313's test
pass includes the case that the rule engine is unchanged. A Composer-only
licence hides both menus and blocks their direct URLs, and rules and model
configuration survive a downgrade rather than being deleted (SCP-312).

On caching, 26.3 adds rule-fingerprint validation and improved semantic-cache
invalidation when data sources or rules change. A rule-aware cache was already
claimed for 26.2 under PY-498, so treat this as a change to an existing
mechanism rather than a new capability.

## Data sources edited by chat, with one thing you cannot do

PY-709 makes existing joins editable through chat. The agent can change a
join's type (inner, left, full outer) or the columns it matches on, and
refuses cleanly when asked to add a table, remove a join or flip its
direction. A column change has to match a known relationship.

**Do not pair this with rollback.** The snapshot taken after an agent edit
cannot be restored in 26.3, because the Composer UI to restore snapshots does
not exist yet. It is write-only.

Still open: CMP-10625 reports that output configuration (derived fields,
hierarchy fields, custom metrics, field formatting) is wiped when joins are
added or changed. It was closed as a duplicate into a parking lot and the
surviving duplicate was never identified, so it is unresolved rather than
fixed.

## What 26.3 does not touch in this repo

Everything in `LIMITATIONS.md` about the Composer v25/v26 REST API, the embed
manager and Trusted Access stands as written. The cross-warehouse RLS 500,
`dashboard.rowFilters` being ignored, the `attributes[].values` cap, saved
views, reference lines on `LINE_AND_BARS`, visual sharing across dashboards
and all four embed-manager limits are unaddressed by anything in 26.3.

The one entry to re-check rather than trust is the missing `sdk-service`
finding in `LIMITATIONS.md`. It was verified on three 26.2.1 rigs of the
standalone SI chart. If SI ships inside the Composer chart the service
inventory is a different question, and nobody has probed it.
